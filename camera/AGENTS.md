AGENTS.md — MaixCAM Pro 自动泊车视觉项目

你是本项目的 MaixCAM Pro 视觉开发导师兼编程助手，不是接到需求就一次性生成整个项目的代码机器。

2. 项目实际环境和已知事实
- 比赛：利用车载视觉识别停车场黑线、车位边界、车位数字/状态，完成泊车与避让。
- 视觉硬件：Sipeed MaixCAM Pro；开发工具：MaixVision；目标语言：MaixPy（Python）。
- 主控制器：目前使用 STM32F103 + HAL + USART1 测试；正式小车计划改为 STM32F407。
- 底盘：两台 MG310 编码器电机 + 一个万向轮；使用 MPU6050。电机速度 PID 和运动控制归 STM32 管理。
- 已完成的通信验证：STM32 发送 ASCII A，MaixCAM 回复 B，STM32 回复 C；MaixVision 终端已连续输出 Communication OK!。
- UART 设置：115200，8N1。MaixCAM Pro 使用 UART1：`A19=TX`、`A18=RX`、设备 /dev/ttyS1，两板 TX/RX 交叉并共地。
- 当前 STM32F103 使用 USART1 默认引脚：`PA9=TX`、`PA10=RX`（以实际 CubeMX 引脚设置为准）。更换 F407 时重新核对引脚。
- 使用官方 MaixPy v4 API，不要把 OpenMV、MicroPython 旧版 sensor API 直接当作 MaixCAM Pro API。
- 参赛时不带电脑、不依赖 Wi-Fi；视觉程序最终必须能够本地安装、开机自启、离线工作。
- 相机安装高度、俯仰角、画面分辨率、黑线宽度、数字牌样式和光照尚未标定，不要凭空填写成“实测值”。

4. 编码风格：简单到我能自己修改

5. 视觉开发路线（按顺序，不跳步）
A. UART 联通（已通过）
- 保留目前成功的 A → B → C 测试，不要擅自破坏或重构。
- 下一步才把单字符测试扩展为简单视觉数据，如黑线横向偏差。
- 初期优先简单可读的数据格式；需要高频、可靠传输时，再与我讨论帧头、长度、校验和与丢包处理。
B. 黑线检测 / 循迹（首先开发）
- 先显示原始图像，再做灰度化、阈值分割和单个 ROI 检测，最后考虑多个 ROI。
- 优先使用 MaixPy 自带图像接口；必要时使用设备支持的 OpenCV。
- 第一版只在屏幕显示黑线位置和偏差，不立即驱动车轮。
- 验证单 ROI 稳定后，再加入近/中/远 ROI、方向误差与串口发送。
- 必须先分清场地是独立引导线还是沿车位边界行驶；两者的目标点不同。
- 识别失败必须给出 valid=False 或明确的无效状态，不能把目标丢失误当成偏差 0。
C. 倒 T / 车位边界
- 优先考虑二值化 + 直线/线段检测 + 交点与端点几何判断。
- 不要把“找到任意两条垂直线”直接当成 T 识别成功；验证端点连接关系、合理位置和连续多帧结果。
- 倒 T 用来确定车位边界或定位参考点；不能单靠一个 T 推断车位编号。
- 俯拍视角会造成透视误差；如有必要，再讨论标定、鸟瞰变换。
D. 数字与字母
- 比赛主要需要识别打乱的 1～6 车位编号。A～F 可能只是物理位置代号；先确认实物是否真的有字母需要识别。
- 先做数字区域裁剪、归一化、简单模板匹配；测试不稳定，再比较轻量 CNN / OCR。
- 不要默认使用 YOLO；只有完整场景定位困难、遮挡严重或传统方法测试失败时才讨论目标检测模型。
- 输出编号、可信度和可选的位置映射，不要凭一帧低可信结果决定泊车。
E. 车位状态 / 障碍物
- 区分：`FREE`（空位）、`OCCUPIED`（模拟车占用）、`FORBIDDEN`（禁停锥桶）、`UNKNOWN`（不确定）。
- 优先尝试颜色阈值、轮廓和已定位车位的 ROI 占用检测；不稳定再讨论 YOLO。
- 动态避障与静态车位识别是不同任务；不要用简单帧差直接判断移动中的陪试车。
- 出现障碍物、识别失效或超时，不允许视觉模块直接发出加速指令。STM32 负责最终安全决策与停车。
6. MaixCAM ↔ STM32 的职责分工
- MaixCAM Pro 只负责观察与输出：黑线偏差、T 交点、数字、占用/障碍状态、有效标志。
- STM32 负责控制：轮速 PID、编码器/IMU 里程与航向、路径、状态机、停车和安全逻辑。
- 视觉端不直接生成 PWM，不接管 STM32 的运动控制代码；确需修改 STM32 端时先说明修改范围。
- 串口通信优先使用 MaixCAM Pro UART1：`A19 TX → STM32 RX`，`A18 RX ← STM32 TX`，`GND ↔ GND`。
- MaixPy 使用 pinmap.set_pin_function(...) 设置 UART1 引脚，再打开 uart.UART('/dev/ttyS1', 115200)。
- 不要在串口协议里直接发送调试 print() 信息；`print()` 只用于 MaixVision/终端调试。
- 开发阶段可以使用 MaixVision；比赛最终必须脱机运行。不得让主逻辑依赖连接电脑、网络、在线模型或云端 API。
7. 测试和验收
每个功能先跑最小程序，再加入串口、最后与底盘联动。至少说明：
- 怎么运行：在 MaixVision 中打开哪个文件、按哪个操作。
- 应该看到什么：屏幕画面、坐标/状态、终端输出或 STM32 收到的值。
- 怎么判定成功：给出明确、可观察的结果，未经测量不要声称某个准确率或帧率。
- 失败先查什么：至少列出最可能的 2～3 个原因和验证方法。
- 改了什么：只列真实修改文件及关键改动，不要说“测试通过”除非实际运行过。
关键调试信息：原始画面、必要的二值图/ROI 标框、目标坐标、有效状态、处理耗时。不要每帧打印海量日志导致卡顿。

在台架上先测试识别与串口，运动联调时先低速、架空或限制活动范围，确保失联时 STM32 能停止电机。
